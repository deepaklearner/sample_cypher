# ✅ **Goal**

Determine if the *incoming* EDW → MySQL → Neo4j account **should be**:

* **PrimaryAuth = true** (Primary account)
* **PrimaryAuth = false** (Secondary account)

---

# 🧠 **Understanding Your Rules**

You told me:

> PrimaryAuth is **not present in EDW**.
> It is computed by a rule when accounts arrive.

### The rule:

A user can have a *PrimaryAuth account* if:

1. `targetSystem` ∈ **['CORP', 'CSARMARK', 'CVS']**
2. `extensionAttribute3` contains **"cloud"**
3. The user has **no existing account in Neo4j marked as PrimaryAuth=true**

If these conditions are met → **this account becomes PrimaryAuth=true**

If the user **already has a primary**, OR the new account does not match the criteria → **this is Secondary**

# ✔️ NEW Computation Logic (based on EDW data ONLY)

To compute *what SHOULD BE* PrimaryAuth based on EDW:

### **Step 1: Identify if the incoming account is eligible**

```
isEligible = (targetSystem in ['CORP','CSARMARK','CVS'])
             AND (extensionAttribute3 contains 'cloud')
```

If `isEligible = FALSE` →
→ `PrimaryAuth = false` (Secondary)
→ Done.

---

### **Step 2: See if this is the first eligible account for this user in the **input EDW dataset**

Before checking Neo4j, we must check EDW accounts (because EDW could be sending multiple accounts for same user in a batch).

```
EDWEligibleAccounts = all EDW accounts for user that satisfy eligibility rule

IF EDWEligibleAccounts count == 1  AND incoming account is that one:
       PrimaryAuth = true
ELSE IF EDWEligibleAccounts count > 1:
       ❗ Ambiguous → reject based on bad data
ELSE:
       PrimaryAuth = false
```

This defines the “correct” PrimaryAuth *expected* from EDW.

---

### **Step 3: Compare against Neo4j**

Now compare the computed EDW PrimaryAuth vs the existing Neo4j PrimaryAuth:

| Computed from EDW | Neo4j value | What to do                                |
| ----------------- | ----------- | ----------------------------------------- |
| true              | true        | OK—no change                              |
| true              | false       | Need to update Neo4j → assign PrimaryAuth |
| false             | true        | Need to demote Neo4j primary (set false)  |
| false             | false       | OK—no change                              |

# 📌 **Full Algorithm (final version)**

### **Input: incoming EDW account**

```
UserID, targetSystem, extensionAttribute3
```

### **STEP A — Check eligibility**

```
if targetSystem in [CORP, CSARMARK, CVS]
and extensionAttribute3 contains "cloud":
    eligible = true
else:
    eligible = false
```

### **STEP B — Count all eligible EDW accounts for the user**

(you need to evaluate EDW batch or MySQL stage table)

```
eligibleCount = number of EDW accounts for this user that meet eligibility
```

### **STEP C — Compute PrimaryAuth**

```
if eligible == false:
    computedPrimaryAuth = false

else if eligibleCount == 1:
    computedPrimaryAuth = true       // incoming is the only eligible one

else if eligibleCount > 1:
    REJECT → data inconsistent

else:
    computedPrimaryAuth = false
```

### **STEP D — Compare to Neo4j**

Retrieve user’s accounts from Neo4j:

```
neo4jPrimaryExists = true/false
```

Then:

* If `computedPrimaryAuth == true` AND `neo4jPrimaryExists == false`
  → Assign PrimaryAuth to this account
* If `computedPrimaryAuth == false` AND `neo4jPrimaryExists == true`
  → And this account is NOT the primary in Neo4j → Secondary
* If mismatch → Update Neo4j accordingly
