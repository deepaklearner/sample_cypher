Got it ✅ — you have **two data sources** (MySQL and Neo4j) containing entitlement records, and you want to:

1. Find **new rows** in MySQL (not present in Neo4j).
2. Find **modified rows** where any of `entitle_desc`, `risk_rating`, `priv`, or `resource_type` differ for the same `(entitle_name, entitle_source)` key.
3. Do this **efficiently** with **large datasets** using **pandas**.

Let’s go step-by-step and focus on **memory and speed optimization**.

---

### ⚙️ Step 1: Load the data efficiently

Make sure to load only needed columns and use efficient dtypes.

```python
import pandas as pd
import numpy as np
import pymysql
from neo4j import GraphDatabase

# Example: Fetching from MySQL
mysql_query = """
SELECT entitle_name, entitle_source, entitle_desc, risk_rating, priv, resource_type 
FROM entitlements;
"""
mysql_df = pd.read_sql(mysql_query, mysql_connection)

# Example: Fetching from Neo4j
neo4j_query = """
MATCH (e:Entitlement)
RETURN e.entitle_name AS entitle_name,
       e.entitle_source AS entitle_source,
       e.entitle_desc AS entitle_desc,
       e.risk_rating AS risk_rating,
       e.priv AS priv,
       e.resource_type AS resource_type
"""
neo4j_df = pd.DataFrame(neo4j_session.run(neo4j_query).data())
```

---

### ⚙️ Step 2: Optimize dtypes (saves memory)

Convert categorical-like columns to `category` and normalize text.

```python
for col in ['entitle_name', 'entitle_source', 'resource_type', 'priv']:
    mysql_df[col] = mysql_df[col].astype('category')
    neo4j_df[col] = neo4j_df[col].astype('category')

mysql_df['risk_rating'] = pd.to_numeric(mysql_df['risk_rating'], errors='coerce')
neo4j_df['risk_rating'] = pd.to_numeric(neo4j_df['risk_rating'], errors='coerce')
```

---

### ⚙️ Step 3: Use merge with indicator for comparison

This is **vectorized**, so it’s very fast.

```python
merged = mysql_df.merge(
    neo4j_df,
    on=['entitle_name', 'entitle_source'],
    how='left',
    suffixes=('_mysql', '_neo4j'),
    indicator=True
)
```

---

### ⚙️ Step 4: Identify **new rows**

These exist in MySQL but not in Neo4j.

```python
new_rows = merged[merged['_merge'] == 'left_only']
new_rows = new_rows[
    ['entitle_name', 'entitle_source', 'entitle_desc_mysql', 'risk_rating_mysql', 'priv_mysql', 'resource_type_mysql']
]
```

---

### ⚙️ Step 5: Identify **modified rows**

Compare columns row-wise efficiently using vectorized operations.

```python
# Only rows that exist in both
common = merged[merged['_merge'] == 'both'].copy()

# Create boolean mask for changed fields
changed_mask = (
    (common['entitle_desc_mysql'] != common['entitle_desc_neo4j']) |
    (common['risk_rating_mysql'] != common['risk_rating_neo4j']) |
    (common['priv_mysql'] != common['priv_neo4j']) |
    (common['resource_type_mysql'] != common['resource_type_neo4j'])
)

modified_rows = common[changed_mask][[
    'entitle_name', 'entitle_source',
    'entitle_desc_mysql', 'entitle_desc_neo4j',
    'risk_rating_mysql', 'risk_rating_neo4j',
    'priv_mysql', 'priv_neo4j',
    'resource_type_mysql', 'resource_type_neo4j'
]]
```

---

### ⚙️ Step 6: (Optional) Further optimization for very large data

If datasets are huge (millions of rows):

* ✅ Ensure both are **sorted by key** (`entitle_name`, `entitle_source`) before merging — speeds up the merge.
* ✅ Use `merge(..., sort=False)` to prevent sorting overhead.
* ✅ If data is too large for memory:

  * Use **chunked processing**: read MySQL/Neo4j data in batches.
  * Or use **Dask DataFrame** (drop-in replacement for pandas).

Example with sorting optimization:

```python
mysql_df.sort_values(['entitle_name', 'entitle_source'], inplace=True)
neo4j_df.sort_values(['entitle_name', 'entitle_source'], inplace=True)

merged = pd.merge(
    mysql_df, neo4j_df,
    on=['entitle_name', 'entitle_source'],
    how='left',
    suffixes=('_mysql', '_neo4j'),
    indicator=True,
    sort=False
)
```
